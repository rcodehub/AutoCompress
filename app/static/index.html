Folders to compress

Every sub-folder of these folders becomes its own .rar archive. Use the container path - the path as seen inside this container - not the /mnt/user/... path on your server. The list below shows what has been mapped.

Archive & checksum

Blank: Show/ becomes Show.rar in the same source folder. Must not be inside a source folder.
Use the second option when several sources could contain folders with the same name.
The CRC is that of the finished .rar file, so it can be checked later with the Check CRCs button or any SFV tool.
Archives already in the source/output folders that have no checksum yet get one (renamed, or an SFV written). Parts of split sets are never renamed; they get an SFV. Use a dry run first.
On: extracting gives Show/.... Off: only the contents are stored.

Compression

Best is the smallest and slowest.
Lets WinRAR/rar repair a damaged archive. 0 = none. 15 = repairs up to roughly 15% damage, for about 15% more space.
Bigger can compress better but needs more memory (per folder being compressed). Auto lets RAR choose.
0 = RAR decides (normally all cores).
0 = one file. 4096 = 4 GB parts: Show.part1.rar, .part2.rar ...
Smaller for many similar files, but extracting one file means reading more, and damage affects more files.
One per line, file or folder names with wildcards, matched at every level. When this is used, the file-count check after compressing is skipped (the archive test still runs).

Password (optional)

Without the password nobody can even list what is inside.
The password is stored in plain text in /data/settings.json (readable only by the container) and is never sent back to the browser. If you lose it, the archives cannot be opened. It only applies to archives created from now on.

After compressing

Runs rar t on the finished archive and checks that it holds as many files as the folder. The folder is only touched after this succeeds. A folder that changed while it was being compressed is never touched.
Recycle Bin puts the folder in .Recycle.Bin at the root of its share, in the same place as files deleted over SMB when the Unraid Recycle Bin plugin is installed (the plugin then lists it and empties it on its schedule). The share itself, or all shares (/mnt/user), must be mapped into the container. With Keep, a folder is not compressed again while an archive with its name exists.
Must be outside the source folders. Folders land in <move folder>/<source folder name>/<folder>; name clashes get a .1, .2 suffix. Use the same kind of path as the sources (don't mix /mnt/user and /mnt/diskN) so the move is instant.
One per line, matched on the folder name. Wildcards allowed.

Schedule & performance

Otherwise scans only run when you press Run now.
Counted from the end of the previous scan.
Each one runs its own RAR, so memory use multiplies. 1-2 is usually right; more helps on fast storage with many cores.
Leaves a folder alone when anything in it changed in the last N minutes, so a copy or download in progress is not archived half-written. Skipped folders are listed in the log. 0 = never skip.
A folder that failed is not retried by scheduled scans until its contents change; Run now always tries again.

Permissions

Also applied to folders this app creates (output, move).
666 = everybody read/write
777 = everybody read/write/open
Unraid's usual owner is nobody:users = 99:100.

RAR program

RAR is proprietary software by RARLAB (the rar command from Debian's non-free repository). It runs in trial mode until you register it. If you own a licence, put your rarreg.key file in the app data folder (/data) and restart the container.

Compress a folder now

A one-off job. It ignores the scanned folders and the schedule and uses your compression settings (level, recovery record, checksum, password...).

The folder is scanned like a source folder: if it contains sub-folders, each sub-folder becomes its own archive and files directly inside it are left alone. Only a folder without sub-folders is compressed as a whole.
